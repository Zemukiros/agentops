pgvector or a dedicated vector database?

Choose pgvector when a team already runs PostgreSQL, the collection is modest (up to tens of millions of vectors), and queries mix similarity with relational filters. One database means one backup, one access-control model, and transactional consistency between rows and their embeddings.

A dedicated vector database is a better fit for very large collections, strict low-latency requirements at high query volume, or when the vector workload must scale independently of the transactional database.
